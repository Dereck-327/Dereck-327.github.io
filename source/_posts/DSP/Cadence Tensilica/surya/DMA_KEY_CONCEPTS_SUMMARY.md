# DMA 关键概念图解（fft_size = 4096）

## 1. transfer_block_qty 是块的数量，不是单个块

```
一个 chirp 的完整数据传输:

BBE 输出 (4096 样本 = 8192 字节):
┌──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
│ 块0  │ 块1  │ 块2  │ 块3  │ 块4  │ 块5  │ 块6  │ 块7  │
│1024B │1024B │1024B │1024B │1024B │1024B │1024B │1024B │
│512样本│512样本│512样本│512样本│512样本│512样本│512样本│512样本│
└──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘
  ↓Trig  ↓Trig  ↓Trig  ↓Trig  ↓Trig  ↓Trig  ↓Trig  ↓Trig
  
  |<---------------- transfer_block_qty = 8 个块 -------------->|
  |<---------------------- 1 个完整 chirp ---------------------->|

单个块:  1024 字节 = 512 样本   → 只是 1/8 chirp  ❌
所有块:  8192 字节 = 4096 样本  → 完整的 1 chirp ✅
```

## 2. fftshift 硬件实现：DMA 地址偏移搬移频谱

```
BBE 自然输出 (FFT 标准顺序):
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ 块0 │ 块1 │ 块2 │ 块3 │ 块4 │ 块5 │ 块6 │ 块7 │
│ DC  │+freq│     │+Fs/2│-Fs/2│     │-freq│  ↻  │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
  i=0   i=1   i=2   i=3   i=4   i=5   i=6   i=7

            ↓ DMA 搬运时重排地址
            
dest_block_idx = (i + 4) % 8:
  块0 → dest 4      块4 → dest 0
  块1 → dest 5      块5 → dest 1
  块2 → dest 6      块6 → dest 2
  块3 → dest 7      块7 → dest 3

chirp_buffer[j] 中的顺序 (fftshift 后):
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ 块4 │ 块5 │ 块6 │ 块7 │ 块0 │ 块1 │ 块2 │ 块3 │
│-Fs/2│     │-freq│  ↻  │ DC  │+freq│     │+Fs/2│
└─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
位置0  位置1  位置2  位置3  位置4  位置5  位置6  位置7

频谱中心化: 零频 (DC) 移到中间 ✓
无需 CPU 操作: DMA 硬件完成 ✓
```

**代码实现**:
```c
uint16_t dest_block_idx = (i + half_block_qty) % transfer_block_qty;
                        = (i + 4) % 8

descriptor.DestStartAdrs = &chirp_buffer[j] + (dest_block_idx * 1024);
```

## 3. 不是乒乓双缓冲，是单缓冲 + 生产者限速

### 乒乓双缓冲（理论，当前未采用）:
```
┌─────────────────┐   ┌─────────────────┐
│  Buffer A       │   │  Buffer B       │
│  (帧 N)         │   │  (帧 N+1)       │
└─────────────────┘   └─────────────────┘
       ↑ DSP 处理           ↑ iDMA 写入
       
下一时刻交换:
┌─────────────────┐   ┌─────────────────┐
│  Buffer A       │   │  Buffer B       │
│  (帧 N+2)       │   │  (帧 N+1)       │
└─────────────────┘   └─────────────────┘
       ↑ iDMA 写入          ↑ DSP 处理
```

### 实际实现（单缓冲 + 触发门控）:
```
只有一份缓冲区:
┌──────────────────────────────────┐
│  chirp_buffer[4][4096]           │
│  ┌────┬────┬────┬────┐           │
│  │ [0]│ [1]│ [2]│ [3]│  4 chirps │
│  └────┴────┴────┴────┘           │
└──────────────────────────────────┘
        ↑              ↑
    帧 N 写入      帧 N+1 覆盖（但安全）

时序保证:
─────────────────────────────────────────────→ 时间

BBE FFT:  [━━━━━━━━ 2ms ━━━━━━━━][━━━━━ 帧N+1 ━━━━━]
               ↓ 完成              ↓ 第一个触发
               
iDMA:          [搬运 12μs][══等待触发══════][搬运帧N+1]
                         ↑ Twait 阻塞
                         
DSP:                     [处理 0.33ms]
                         |<─ 安全 ─>|

关键: DSP 处理(0.33ms) << BBE 生成下一帧的时间(2ms)
     → 处理期间 iDMA 等待 BBE 触发，不会覆盖 ✓
```

### 保护机制对比:

| 机制 | 乒乓双缓冲 | 当前单缓冲设计 |
|------|-----------|---------------|
| **空间隔离** | ✅ 两份独立内存 | ❌ 只有一份 |
| **时间隔离** | 无需（空间已隔离）| ✅ BBE 触发门控 + 速度差 |
| **内存开销** | 2× (64 KB) | 1× (32 KB) |
| **复杂度** | 需切换逻辑 | 简单（循环链表） |
| **安全性** | 绝对安全 | 安全（时序保证） |

### 核心同步代码（main.c）:

```c
while (1) {
    // 1. 等待一帧完成
    while (READ_IDMA_NUMDESC != 214);      // 250 - 36 = 214
    
    // 2. 立即补充配额（允许 iDMA 继续，但会被 BBE 触发阻塞）
    WRITE_IDMA_NUMDESCINCR(36);             // 214 → 250
    
    // 3. 内存屏障（DMA 数据对 DSP 可见）
    XT_MEMW(); XT_EXTW();
    
    // 4. 处理当前帧（此时 iDMA 等待 BBE 触发，不会覆盖）
    for (i = 0; i < 4; i++)
        processEngineUpdate(&core, &event);
}
```

### 关键触发门控:

```c
// 数据描述符配置
descriptor_control.Twait = ExtTriggerNeeded;   // 必须等 BBE 触发
descriptor_control.Trig  = SendTrigger;        // 完成后发送触发

// iDMA 执行流程:
1. 处理完 Desc 35 (帧 N 的最后一个描述符)
2. 进入 Desc 36 (Loop Descriptor) → 跳回 Desc 0
3. Desc 0 检测到 Twait=ExtTriggerNeeded → 等待 TrigIn
4. BBE 正在计算帧 N+1 FFT (~2ms)，尚未产生 TrigOut
5. iDMA 阻塞等待...
6. DSP 此时处理帧 N 数据 (~0.33ms) → 安全 ✓
7. 2ms 后 BBE 产生第一个 TrigOut
8. iDMA 收到 TrigIn → 开始传输帧 N+1 的第一块
```

## 总结

✅ **transfer_block_qty = 8** 是块的数量，8 个块合起来 = 1 个完整 chirp  
✅ **fftshift** 通过 DMA 目标地址偏移实现，零 CPU 开销  
✅ **单缓冲安全** 依赖 BBE 外部触发门控 + 速度差，而非双缓冲  

当前设计优势：
- 内存占用减半（32KB vs 64KB）
- 实现简洁（无需切换逻辑）
- 硬件卸载（fftshift 零开销）
- 时序安全（84% 处理富余）
